# Backup Strategy

本文档描述 GateDemo 项目中 Redis 持久化、备份及未来数据库备份策略。

## 1. Redis 持久化

### 1.1 RDB（快照）

- **机制**：周期性将内存快照写入磁盘（`BGSAVE`）
- **配置**：`save 900 1`、`save 300 10`、`save 60 10000` 等规则，或自定义 `BGSAVE` 策略
- **数据目录**：`dir /data/redis`
- **备份位置**：RDB 文件默认与数据目录相同，可配置定时任务复制至异地存储

### 1.2 AOF（Append Only File）

- **机制**：记录每次写命令，重启时重放以恢复
- **配置**：`appendonly yes`，`appendfsync everysec`（平衡性能与 durability）
- **数据目录**：AOF 文件通常与 RDB 同目录

### 1.3 持久化配置建议

- 生产环境建议同时开启 RDB + AOF
- RDB 用于快速恢复；AOF 用于更细粒度恢复（RPO 更小）

## 2. Redis 备份

### 2.1 备份流程

- 利用 Redis `BGSAVE` 生成 RDB 快照
- 或直接复制 AOF 文件（需注意 `appendfsync` 与 fsync 策略）
- 将备份文件上传至对象存储或异地存储（S3、OSS 等）
- 按保留策略定期清理历史备份

### 2.2 恢复 SOP（从 RDB 或 AOF）

1. 停止 Redis 实例
2. 将备份的 RDB 或 AOF 文件放置于 `dir` 指定目录
3. 若使用 AOF，确保 `appendonly yes`；若仅 RDB，可临时关闭 AOF
4. 启动 Redis，观察启动日志确认加载成功
5. 验证关键 key 是否存在，必要时执行简单读写测试

### 2.3 演练

- 在测试环境定期执行恢复演练，验证 SOP 有效性
- 记录 RTO（恢复时间目标）与 RPO（恢复点目标），用于容量与 SLA 规划

## 3. 数据库备份（若引入）

### 3.1 适用场景

- 若项目后续引入 MySQL、PostgreSQL 等关系型数据库，需配置定期备份

### 3.2 备份方式

- **逻辑备份**：`mysqldump`、`pg_dump` 等，适合小中型数据量
- **物理备份**：基于存储快照或数据库自带工具，适合大数据量

### 3.3 配置建议

- 备份脚本或工具将备份文件上传至异地存储
- 根据 RPO/RTO 确定备份频率（如每日全量 + 每小时增量）
- 保留策略：如保留最近 7 天全量 + 30 天增量

### 3.4 恢复 SOP

- 编写数据库恢复 SOP 文档，包含从备份恢复的完整步骤
- 在测试环境定期演练

### 3.5 当前状态

- 若尚未引入数据库，在文档中标注为 **「待引入时执行」**
