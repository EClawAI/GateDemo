## 1. TokenBlacklistService 分析

### 概述
`TokenBlacklistService` 是一个基于 Redis 实现的 Token 黑名单服务，用于处理 JWT Token 的失效管理。

### 核心功能
- 将登出或失效的 Token 的 jti 加入黑名单
- 检查 Token 是否在黑名单中

### 关键方法

#### addToBlacklist
```java
public void addToBlacklist(String jti, long ttlSeconds) {
    if (jti == null) return;
    try {
        redisOperations.opsForValue().set(BLACKLIST_PREFIX + jti, "1", ttlSeconds, TimeUnit.SECONDS);
        logger.info("Token jti={} added to blacklist, ttl={}s", jti, ttlSeconds);
    } catch (Exception e) {
        logger.error("Failed to add token to blacklist: {}", e.getMessage());
    }
}
```

#### isBlacklisted
```java
public boolean isBlacklisted(String jti) {
    if (jti == null) return false;
    try {
        return Boolean.TRUE.equals(redisOperations.hasKey(BLACKLIST_PREFIX + jti));
    } catch (Exception e) {
        logger.error("Failed to check blacklist: {}", e.getMessage());
        return false;
    }
}
```

### 设计特点
- **Redis 存储设计**：使用 `token:blacklist:{jti}` 作为键，值固定为 "1"
- **TTL 自动清理**：黑名单条目与 Token 有效期同步过期
- **容错设计**：Redis 操作失败时返回安全默认值

## 2. TokenService 分析

### 概述
JWT Token 验签服务，Gate 端只做验签，不签发。

### 核心方法

#### validateToken
```java
public Claims validateToken(String token) {
    try {
        return Jwts.parser()
                .verifyWith(secretKey)
                .build()
                .parseSignedClaims(token)
                .getPayload();
    } catch (ExpiredJwtException e) {
        logger.warn("Token expired: {}", e.getMessage());
    } catch (JwtException e) {
        logger.warn("Invalid token: {}", e.getMessage());
    }
    return null;
}
```

#### getPlayerId
```java
public Long getPlayerId(String token) {
    Claims claims = validateToken(token);
    if (claims != null) {
        String sub = claims.getSubject();
        return sub != null ? Long.parseLong(sub) : null;
    }
    return null;
}
```

#### getJti
```java
public String getJti(String token) {
    Claims claims = validateToken(token);
    return claims != null ? claims.getId() : null;
}
```

### 设计理念
- **单一职责**：Gate 只负责验签，Token 签发由 Login 服务负责
- **密钥管理**：通过配置文件注入 JWT 密钥

## 3. GateClusterManager 分析

### 概述
Gate 集群注册管理器，负责将 Gate 实例注册到 Redis，实现节点自动发现。

### 核心机制

#### 心跳注册
```java
scheduler.scheduleAtFixedRate(this::register, REFRESH_INTERVAL_SECONDS, REFRESH_INTERVAL_SECONDS, TimeUnit.SECONDS);
```

#### register 方法
```java
private void register() {
    String key = KEY_PREFIX + gateConfig.getId();
    Map<String, Object> value = new HashMap<>();
    value.put("host", gateConfig.getHost());
    value.put("port", gateConfig.getPort());
    value.put("tcpPort", gateConfig.getTcp().isEnabled() ? gateConfig.getTcp().getPort() : null);
    value.put("timestamp", System.currentTimeMillis());

    try {
        redisTemplate.opsForValue().set(key, value, TTL_SECONDS, TimeUnit.SECONDS);
    } catch (Exception e) {
        logger.error("Failed to register gate to Redis: {}", e.getMessage());
    }
}
```

### 设计参数
- **TTL**: 60 秒
- **心跳间隔**: 30 秒
- **键格式**: `gate:cluster:{gateId}`

## 5. scheduleAtFixedRate 方法解析

| 参数 | 含义 |

### 与 scheduleWithFixedDelay 的区别

- **scheduleWithFixedDelay**: 固定延迟，任务完成后等待指定时间再执行

                conn.streamConnected = false;
                scheduleReconnect(conn);
            }

## 9. gRPC Stream 中 onNext 的双向作用

### 核心概念
在 gRPC Bidirectional Stream 中，`onNext` 方法的作用取决于调用者：

```
┌─────────────────────────────────────────────────────────────────┐
│                    gRPC Bidirectional Stream                     │
│                                                                  │
│   Gate 端                                          Game 端       │
│   ─────────                                        ──────        │
│                                                                  │
│   ┌─────────────────┐                           ┌──────────────┐ │
│   │ gameStreamSender│ ─── onNext(message) ──▶ │ 服务端接收   │ │
│   │ (我们调用)      │     发送消息              │ onNext()     │ │
│   └─────────────────┘                           └──────────────┘ │
│                                                                  │
│   ┌─────────────────┐                           ┌──────────────┐ │
│   │ 我们实现的       │ ◀── onNext(message) ──────│ gameStream   │ │
│   │ StreamObserver  │     接收消息               │ (Game 调用)  │ │
│   │ 的 onNext()    │                           └──────────────┘ │
│   └─────────────────┘                                              │
│                                                                  │
└─────────────────────────────────────────────────────────────────┘
```

### 两处 onNext 的区别

| 场景 | 哪边的 onNext 被调用 | 说明 |
|------|---------------------|------|
| 我们调用 `gameStreamSender.onNext(msg)` | **Game 服务**的 onNext 被调用 | 我们在发送消息 |
| Game 调用它的方法发送消息给我们 | **我们创建的** StreamObserver 的 onNext 被调用 | 我们在接收消息 |

### 关键点
- **发送消息**：`gameStreamSender.onNext(message)` → Game 收到
- **接收消息**：Game 推送消息 → 我们的 `StreamObserver.onNext(message)` 被调用
- 发送和接收是**两条独立的通道**，不会互相触发

       pm.setMsgType(message.getMsgType());
       pm.setPlayerId(playerId);
       pm.setBody(body);

           // 单发给指定玩家 (echo)
           playerService.sendToPlayer(playerId, pm);

           // 广播给所有在线玩家 (broadcast)
           for (Long pid : playerService.getAllOnlinePlayerIds()) {
               playerService.sendToPlayer(pid, pm);
           }
       }
   });
