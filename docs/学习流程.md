# 游戏网关服务 - 推荐学习流程

本文档为初学者提供一条清晰的学习路径，帮助你从浅入深理解整个游戏网关服务的实现。

## 学习前提

- 熟悉Java基础语法
- 了解Spring Boot框架
- 理解TCP/WebSocket通信基本概念

---

## 第一阶段：理解核心概念（1-2小时）

### 1.1 什么是游戏网关？

**核心问题：** 为什么需要网关？客户端不能直接连接游戏服吗？

**学习目标：** 理解网关在游戏架构中的作用

**推荐阅读：**
- 架构图：见 `docs/设计文档.md` 第一章
- 功能职责：
  1. 协议转换（WebSocket → gRPC）
  2. 消息路由（根据消息类型分发）
  3. 连接管理（玩家在线状态）
  4. 安全防护（认证、限流）

### 1.2 理解网络协议

**核心概念：**
- TCP vs UDP
- WebSocket：全双工通信协议
- 消息头+消息体的协议格式

**动手实验：**
1. 启动项目：`mvn spring-boot:run`
2. 用浏览器ws客户端连接：`ws://localhost:8888`
3. 发送一条登录消息，观察日志

---

## 第二阶段：消息协议（2-3小时）

### 2.1 消息格式设计

**学习文件（按顺序）：**

1. **MessageHeader.java** - 消息头
   - 理解14字节固定头部的设计
   - 理解flags位运算（压缩、加密、模式）
   - 消息模式：REQUEST/RESPONSE/PUSH

2. **MessageBody.java** - 消息体接口
   - 理解序列化/反序列化概念
   - toBytes() vs toJson() 的区别

3. **JsonMessageBody.java** - JSON实现
   - Jackson ObjectMapper的使用
   - Map<String, Object> 的灵活性

4. **WrappedMessage.java** - 包装类
   - 消息头+消息体的组合

### 2.2 编解码器

**学习文件：**

1. **GameMessageEncoder.java** - 编码器
   - 理解Netty的MessageToByteEncoder
   - 理解二进制协议的写入顺序
   - 理解DEFLATE压缩算法

2. **GameMessageDecoder.java** - 解码器
   - 理解Netty的ByteToMessageDecoder
   - 理解如何从二进制流解析消息

**重点理解：**
- 编码/解码的顺序必须一致
- 粘包/半包问题的处理（通过bodyLength）
- 压缩/解压缩流程

### 2.3 消息ID管理

**学习文件：**

1. **MessageIdGenerator.java** - FNV哈希算法
2. **MessageIdRegistry.java** - 消息ID注册表

**理解要点：**
- 为什么用哈希而不是自增ID？
- 消息名称格式：`模块.操作`（如 `auth.login`）

---

## 第三阶段：连接管理（2-3小时）

### 3.1 连接模型

**学习文件：**

1. **PlayerConnection.java** - 连接模型
   - 状态机：CONNECTING → AUTHENTICATED
   - 最后心跳时间

2. **ConnectionManager.java** - 连接管理器 ⭐重点
   - ConcurrentHashMap的使用
   - 心跳检测机制
   - 定时任务调度

### 3.2 WebSocket处理

**学习文件：**

1. **GateNettyWebSocketHandler.java**
   - channelActive: 连接建立
   - channelRead0: 收到消息
   - channelInactive: 连接断开

**理解要点：**
- ChannelPipeline中的Handler链
- 消息的流入流出过程

## 第六阶段：离线消息（2小时）

### 6.1 Redis Stream

**学习文件：**

1. **RedisConfig.java** - Redis配置
2. **MessageQueueProducer.java** - 消息生产者
3. **MessageQueueConsumer.java** - 消息消费者
4. **OfflineMessageService.java** - 离线消息服务 ⭐重点

**理解要点：**
- Redis Stream vs Redis Pub/Sub
- 消费者组概念
- 离线消息策略

### 6.2 消息队列设计

```
玩家A离线
    ↓
消息存入 Redis Stream (game:offline:messages:A)
    ↓
玩家A上线
    ↓
检查消息数量
    ↓
≤200条：逐条推送
>200条：触发relogin
```

## 实战练习建议

步骤：

目标：让所有大于100字节的消息自动压缩

提示：修改 `GameMessageEncoder` 中的压缩阈值

### 练习3：添加限流规则

目标：限制每个玩家每分钟最多发送100条消息

## 常见问题

### Q1: 如何调试网络通信？

A: 
1. 启用WireShark/TcpDump抓包
2. 使用Netty的LoggingHandler
3. 查看日志中的traceId

### Q2: 如何添加新的序列化方式？

A:
1. 实现 `MessageBody` 接口
2. 在编解码器中根据flags选择实现

### Q3: 如何处理粘包问题？

A:
本项目通过固定长度的消息头（bodyLength字段）解决粘包问题，详见 `GameMessageDecoder`
